# LeetCode на TypeScript: решение через тесты

Аналог Go-шаблона: отдельная папка на задачу, решение и табличные тесты рядом.
Используются TypeScript и Vitest. Нужны Node.js 22.12+ и npm.

## Быстрый старт

Распакуйте архив, затем:

```bash
cd leetcode-typescript
npm install
npm run check
```

`npm run check` запускает проверку типов и тесты. Сам Vitest не проверяет типы:
для этого есть отдельная команда `npm run typecheck`.

## Содержимое

- `problems/p0001_two_sum/` — готовое решение и 5 тестовых случаев.
- `problems/p0003_longest_substring/` — упражнение без решения с 10 тестами.
- `template/` — заготовка для новых задач.
- `vitest.config.ts` — конфигурация тестов.
- `tsconfig.json` — строгая проверка типов.

В каждой папке `solution.ts` содержит функцию, `solution.test.ts` — тесты.
Точка входа приложения не нужна: код запускается тестовым раннером.

## Решать упражнение

В `problems/p0003_longest_substring/solution.test.ts` замените `describe.skip`
на `describe`, чтобы включить тесты. Реализуйте функцию в соседнем `solution.ts`.
Задача: найти длину самой длинной непрерывной подстроки без повторяющихся символов.
Например: `abcabcbb` → 3, `bbbbb` → 1. Здесь тестовые строки используют ASCII.

```bash
# Один запуск
npm test -- problems/p0003_longest_substring

# Автоматический перезапуск при изменении файлов
npm run test:watch -- problems/p0003_longest_substring
```

Сначала тесты должны падать с `not implemented`. После реализации добейтесь
успешного прохождения и добавьте свои случаи. Затем выполните `npm run check`.
Упражнение и шаблон изначально пропущены: зелёный запуск не означает, что они решены.

## Новая задача

На macOS/Linux, из корня проекта:

```bash
cp -R template problems/p0015_three_sum
```

1. Замените сигнатуру `solve` на сигнатуру из задачи.
2. Обновите импорт, вызов функции и поля таблицы в тесте.
3. Добавьте входные данные и ожидаемые результаты из условия и свои крайние случаи.
4. Замените `describe.skip` на `describe` и начните решать.

```bash
npm run test:watch -- problems/p0015_three_sum
```

## Команды

```bash
npm test                                     # Все тесты, один запуск
npm test -- problems/p0001_two_sum            # Одна задача
npm test -- problems/p0001_two_sum -t duplicates # Один случай
npm run test:watch                           # Режим наблюдения
npm run typecheck                            # Проверка типов
npm run check                                # Типы + все тесты
```

Табличные тесты оформлены через `test.each(cases)`:

```ts
test.each([
  { s: 'abcabcbb', want: 3 },
  { s: 'bbbbb', want: 1 },
])('$s → $want', ({ s, want }) => {
  expect(lengthOfLongestSubstring(s)).toBe(want);
});
```

Для чисел и строк используйте `.toBe(want)`, для массивов и объектов — `.toEqual(want)`.
Если порядок ответа не важен, нормализуйте его или проверяйте свойства результата.
Two Sum принимает любой порядок двух корректных индексов.
Копирование `[...nums]` защищает исходный одномерный массив от изменения решением;
для вложенных данных при необходимости используйте `structuredClone`.
Для задач с изменением входа на месте проверяйте сам изменённый массив.

## Отправка на LeetCode

Скопируйте функцию и вспомогательные определения из `solution.ts`, убрав `export`.
Тесты и конфигурацию копировать не нужно. Учитывайте ограничения чисел JavaScript:
`number` точно представляет целые только до `Number.MAX_SAFE_INTEGER` по модулю,
а многие побитовые операции работают с 32-битными значениями.
Локальные тесты не заменяют скрытые тесты платформы.

Документация Vitest: https://v4.vitest.dev/guide/
